# architecture-future_2_0
Описание решения
Так как в организации уже реализовано много бизнес логики на существующих компонентах в рамках проекта будет крайне рискованно  пытаться заменить все что реализовано  за годы работы. Оптимальным будет подход  при котором новая архитектура работает параллельно с новой, при этом все новые задачи или изменения в существующем функционале производятся с переходом на новый стек.  Интеграционные процессы так же будут постепенно переноситься с легаси решения Apache Camel  на работу через  DataHub. Это позволяет сделать процесс перехода более плавным и оставляет возможность отката к легаси в случае проблем миграции или новом функционале.
Для реализации целевого решения выбрана реализация спецификации Apache Iceberg, основными компонентами выбраны:
1. Хранение структурированных данных - PostgreSQL
2. Хранение не структурированной информации -  S3 совместимое решение CEPH
4. В качестве инструмента для работы с данными будет использовано ПО Dremio
5. В качестве инструмента управления потоками данных будет использовано ПО DataHub
